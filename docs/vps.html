Why not GitHub Pages?

GitHub Pages serves static files only. It cannot run the bot, hold the Discord token, or host MongoDB. To keep Supportly online 24/7, run it on a host that supports long-running processes: a VPS, or Railway / Fly.io / Render, or your own always-on machine.

No secrets are stored in this repo. Your token lives in the host environment only.

1. Prerequisites

1A Linux VPS (Ubuntu 22.04). 2 vCPU / 4 GB RAM is plenty for a support bot. Note its IP and SSH in as root (or a sudo user with your public key).
2Open ports: 22/tcp for SSH. The bot connects outbound to Discord (no incoming ports needed beyond SSH).

2. Install dependencies

3Install git, Python 3.11, and MongoDB (official repo):
Copy
sudo apt-get update
sudo apt-get install -y git curl gnupg ca-certificates lsb-release

# Python 3.11 (deadsnakes)
sudo add-apt-repository -y ppa:deadsnakes/ppa
sudo apt-get update
sudo apt-get install -y python3.11 python3.11-venv python3.11-distutils

# MongoDB 7.0 (official)
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.gpg \
  | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg] http://repo.mongodb.org/apt/ubuntu $(lsb_release -cs)/mongodb-org/7.0 multiverse" \
  | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org

3. Configure secrets (host only, never in git)

4Start MongoDB on localhost only:
Copy
sudo mkdir -p /data/db /var/log/mongodb
sudo mongod --fork --logpath /var/log/mongodb/mongod.log --dbpath /data/db --bind_ip 127.0.0.1
5Clone the repo and create a secret env file readable by root only. Paste your Discord bot token here — I never see it:
Copy
git clone https://github.com/justsadnyx-ux/supportly.git
cd supportly
python3.11 -m venv .venv
.venv/bin/pip install -q --upgrade pip
.venv/bin/pip install -r requirements.txt

# Create /etc/default/supportly — owned by root, mode 0600
sudo tee /etc/default/supportly >/dev/null <<'ENV'
TOKEN=YOUR_DISCORD_BOT_TOKEN
GUILD_ID=1523251076915265606
SUPPORT_GUILD_ID=1523251076915265606
CONNECTION_URI=mongodb://localhost:27017
UPDATE_CHANNEL_ID=1533409707409018992
STATUS=online
ACTIVITY_TYPE=custom
ACTIVITY_MESSAGE=DM - FOR SUPPORT
DISABLE_AUTOUPDATES=true
ENV
sudo chown root:root /etc/default/supportly
sudo chmod 600 /etc/default/supportly
Prefer a provider secret store?

On Railway/Fly/Render, set the same vars in the dashboard's Secrets instead of the env file.

4. Run the bot (systemd)

6Add a systemd unit so the bot restarts on crash / reboot:
Copy
sudo tee /etc/systemd/system/supportly.service >/dev/null <<'UNIT'
[Unit]
Description=Supportly Discord bot
After=network.target

[Service]
Type=simple
User=supportly
EnvironmentFile=/etc/default/supportly
WorkingDirectory=/opt/supportly
ExecStart=/opt/supportly/.venv/bin/python /opt/supportly/bot.py
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload
sudo systemctl enable supportly
sudo systemctl start supportly

5. Verify

  • sudo journalctl -u supportly -f → look for Logged in as: Supportly#9347 and Status set to: online.
  • Bot status on Discord shows DM - FOR SUPPORT.
  • ?changelog loads from the Pages changelog.
  • ?update reports current vs latest and posts the full latest changelog to #our-bot-updates.

These commands run on the VPS — the bot never depends on GitHub Pages to stay alive.

Optional: auto-deploy from GitHub

Deploy the bot on git push via GitHub Actions → SSH

Add a workflow in .github/workflows/deploy.yml that, on push to master, SSHs into the VPS and runs git pull && systemctl restart supportly. You'd store the VPS SSH key as a GitHub secret. I can write this workflow for you — but only run it after you confirm the SSH key secret is set by you.
