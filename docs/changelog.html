Latest release

Releases

Rendered from CHANGELOG.md, newest first. The same notes are posted to #our-bot-updates on each release.

v1.1.4 · End-to-end auto-update verification

Changed

  • Verification release: confirms the fully automatic update pipeline works end to end -- detect newer version, git pull, post changelog + “Bot has been updated” embed to #our-bot-updates, restart with no manual steps.
v1.1.3 · Auto-update no longer hangs on local hosting

Fixed

  • The GitHub fork-sync API call that ran before git pull on every hosting method (even though only Heroku uses it) could block the check indefinitely when no GitHub token is configured -- leaving the bot stuck on an older version with no notification and no restart. It is now skipped unless running on Heroku.
v1.1.2 · ?update posts only to #our-bot-updates

Changed

  • ?update no longer replies in the channel where it's run -- results post only to the configured update channel (#our-bot-updates).
v1.1.1 · Fully automatic updates

Changed

  • Auto-updates enabled: the bot checks the changelog every 15 minutes and again right after boot.
  • On a newer version it runs git pull, posts the changelog to #our-bot-updates, and restarts itself -- no ?update needed.
  • Each check logs Autoupdate check: current vX, latest vY.
v1.1.0 · Speed pass + emoji fixes

Performance

  • Messages are processed in a single pass: contexts and the thread lookup are built once per message instead of 2-4 times.
  • Reaction emoji are resolved once and cached, invalidating when their config changes.

Fixed

  • Corrupted (double-encoded) emoji made the queued-command reaction and an unsnooze log render as garbled text; now send/display correctly.
v1.0.9 · Unified docs UI + changelog page

Changed

  • Docs site UI unified across index.html, vps.html, and a new changelog.html; shared style.css.
  • ?update is a read-only check; posts the full latest changelog to #our-bot-updates.

Added

  • docs/vps.html VPS deployment guide; optional public health-status badge on the homepage.
v1.0.8 · ?update read-only + Pages polish

Changed

  • `?update` is now a read-only update *check*: it reports the current vs. latest version and posts the full latest changelog to #our-bot-updates, but no longer pulls or restarts the bot.
  • GitHub Pages site (docs/index.html) refreshed with a hand-written design; docs still hosted on Pages (not the bot -- the bot runs locally and reads its token from .env).

Added

  • #our-bot-updates (1533409707409018992) receives the full latest changelog embed on each ?update check.
v1.0.7 · changelog pipeline test release

Changed

  • Release cut to verify the new update-notification + GitHub Pages changelog pipeline end to end.
v1.0.6 · ?about links to docs + repo

Added

  • ?about now links to the support server, the GitHub repo, and the GitHub Pages site.
v1.0.5 · changelog hosted on Pages

Changed

  • Changelog is served from the GitHub Pages site (https://justsadnyx-ux.github.io/supportly/).
v1.0.4 · channel notifications instead of DMs

  • Changelog source now points to the GitHub Pages site (justsadnyx-ux.github.io/supportly); only the latest version is published.
v1.0.3 · update channel + restart note

Improved

v1.0.2 · pipeline test release
